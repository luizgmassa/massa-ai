# Spec — spec-driven: DI per task/phase, not a separate phase

- feature: `spec-driven-di-per-phase`

- scope: 1 requirement (DI-01).

## Background

The user wants the spec-driven workflow to require that **dependency injection (DI) / wiring is performed inside each task or phase as part of that task's own work**, and must **not** be deferred to a separate final "DI", "wiring", or "integration" phase.

## Why

This is the same defect class the existing "Test Co-location" rule already closes for tests (`references/spec-driven/tasks.md` → "Resolving compilation dependencies"): a task that produces code but defers its dependency wiring to a later phase leaves the repository unbuildable and unverifiable at every intermediate commit. If the final wiring phase fails or is skipped, every preceding task is stranded — none of their gates actually proved the code works in context. Per-phase atomic commits lose their meaning when a phase's code cannot run until a phase that comes much later.

The fix mirrors the test-co-location fix: wire dependencies in the task that introduces the code that needs them, or merge the wiring into the earliest task where it becomes runnable. Never collect all wiring into one trailing phase.

## Requirement

### DI-01 — Dependency injection is per-task/per-phase, never a separate final phase

**Behavior:** When planning and executing spec-driven work, dependency injection, module/dependency wiring, container registration, and provider/composition-root setup for a unit of code are done **inside the task (or its phase) that introduces that unit**. A dedicated trailing phase whose purpose is "do all the DI / wire everything together" is prohibited. Each task's gate must pass against code whose dependencies are wired by that task or an earlier one.

**Scope:** `references/spec-driven/tasks.md` (primary rule) + `references/spec-driven/execute.md` (per-task clause). Inherited by `workflows/spec-driven.md` (which loads both references). Regenerate the 4-host skill bundles.

**Acceptance criteria:**

- AC-1: `references/spec-driven/tasks.md` states that DI/wiring is performed in the task/phase that introduces the code needing it, and explicitly prohibits a separate final "DI"/"wiring"/"integration" phase.
- AC-2: The rule sits alongside the existing "Resolving compilation dependencies" guidance (the test-co-location analog) and cross-references it, so the two "don't defer to a trailing task/phase" rules read as one principle.
- AC-3: The `tasks.md` "Rules" section and the phase-planning step (Create Execution Plan) carry the no-trailing-DI-phase constraint, so it is enforced at planning time, not only at execution time.
- AC-4: `references/spec-driven/execute.md` carries a short per-task clause (in the dependency/implementation step) that each task wires its own dependencies and that unwired code is a gate failure, cross-linking `tasks.md` as the authority.
- AC-5: The four host skill bundles are regenerated byte-for-byte and `generate-skill-artifacts.ts --check` reports No drift.
- AC-6: `bun run test:scripts` introduces no new failures vs. baseline (the harness-integrity, skill-artifact-parity, and workflow-harness-contract suites stay green).
