## Executive summary

- **The range is dominated by one enormous PR**: `dc7178c8` (#1139, `feat/shared-coordination-daemon`, merged 2026-07-23) introduces an entirely new **mandatory per-account background coordination daemon** — 192 files, +90,029/-3,477 lines, roughly 86% of the range's total insertions. Everything else in the range either builds on it, hardens it, or fixes fallout from it.
- The daemon enforces a **crash-safe "exact-build admission barrier"**: every CBM process (daemon, CLI, MCP frontend, hook client) must match exact version + build SHA-256 + coordination-ABI + canonical cache-root to interoperate; a mismatch is rejected and logged as a conflict, never silently ignored or split-brained.
- A new **atomic activation-transaction primitive** (`cli/activation_transaction.c`) makes install/update/uninstall crash-safe: stage a candidate beside the target, commit with an optional post-commit validator (auto-rollback on failure), retain the old binary as a backup, finalize (delete backup) or leave it `DEFERRED` on Windows if still mapped.
- **A real production incident and its reversal**: PR #1139 shipped Windows with a launcher+payload binary split (needed because a running `.exe` can't overwrite itself). PR `61a432ca` (#1316) reports this stub was statically indistinguishable from a dropper — Microsoft Defender's ML scored it `Trojan:Win32/Wacatac.B!ml` and **blocked a real release (v0.9.1-rc.1) at the team's own VirusTotal CI gate**. Multiple binary-hardening mitigations (bcrypt-free, stripped, resource-free builds) all still got flagged. The fix removed the stub entirely (~2,500 lines) and moved self-update fully out-of-process into `install.ps1`/`install.sh` on **every** platform, not just Windows.
- **A genuine policy oscillation, the single most notable governance event in the range**: PR #1340 built a sophisticated, evidence-gated mechanism to tolerate a narrow class of proven ML false positives (single-engine, Microsoft, `!ml`-suffixed, backed by real Windows-VM Defender-endpoint scan evidence). One PR later, `f2e97ff7` (#1341) **reverts it completely** by explicit owner decision ("a reputation cost the project is not willing to price in") and adds a grep-based tripwire test so the mechanism can't silently return.
- PR `07197ee6` (#1344, `harden/av-margin-rc2`) is a capstone hardening pass removing every genuinely malware-shaped capability regardless of whether AV was currently flagging it: an executable ELF stack (a build-system omission), opt-out test seams, the daemon's background phone-home update-check thread, dead tar.gz/zip extraction code, SQLite's load-extension surface, predictable/symlink-followable temp files in three subsystems, and non-reproducible build timestamps — backed by a new automated "assert absence of malware-shaped capability" CI gate (`check-binary-composition.sh`).
- That same hardening pass fixed a **real memory-safety-adjacent defect**: `src/pipeline/pass_envscan.c`'s path-joining code used `strncpy` + raw pointer arithmetic that could index past a fixed 512-byte buffer once `root_path` exceeded it, and used `stat()` (not `lstat()`) so a repo-planted symlink could walk the scanner outside the project root.
- A separate, self-contained investigation (issue #581, PR `a3887001`/#1252 plus its two follow-ons `00495a73`/#1274 and `4fda0d90`/#1275) chased a Windows memory-growth leak through ~70 exploratory commits, building a durable **memory-diagnostics framework** (three-way OS/allocator/residual memory map, per-size-class allocator-ownership audit, phase-marked attribution, Windows region census) along the way. Several tried fixes (a connection thread pool, an SQLite page-cache hoist, an early TLS-heap-release attempt, unverified launcher-guard edits, an allocation profiler) were explicitly reverted after failing to hold up; the real root cause was that mimalloc wasn't actually intercepting Windows `malloc()` (fixed by releasing thread-local heaps via a TLS detach callback), compounded by an unrelated arm64 alignment crash in an unverified SQLite page-cache optimization (deleted outright once disproven).
- **A real data-loss bug was fixed inside the daemon PR**: `resolve_store()` used to `cbm_unlink()` (permanently delete) a project's SQLite store file the moment an integrity check returned false — including on a false positive from an overly strict `root_path` character check (issue #557). It now quarantines the file to a timestamped backup path and logs the action instead of deleting it.
- **A real indexing-correctness bug was fixed**: the parallel extraction pipeline hardcoded `INHERITS` for every base-class edge regardless of whether the base was an interface, while the sequential pipeline correctly distinguished `IMPLEMENTS`; on `elasticsearch` (large enough to trigger the parallel path) this produced 11,179 `INHERITS` vs 3 `IMPLEMENTS` edges. Fixed by extracting one shared decision function called from both code paths.
- **A real indexing-scalability bug was fixed**: the directory-discovery walk used a hard 512-entry stack cap that failed indexing outright on repos with very wide directories (dotnet/runtime has 855 sibling directories in one place); replaced with a `realloc`-growable stack.
- Test count grew from **5,604 to 6,768** passing tests (README badge, +1,164) across roughly 120 suites over the range.
- A new nightly `cache-warm.yml` CI workflow fixes a real GitHub Actions cache-isolation cold-start problem: since the test workflow only runs on `pull_request`/`workflow_dispatch` (never on push to `main`), no workflow ever wrote a base-ref cache a PR could fall back to, so every fresh PR built cold; this job builds (never tests) nightly across the full OS matrix purely to keep that cache warm.
- Three packaging ecosystems (Go, npm/Node, PyPI/Python) all gained the **same** hardened "authenticate-then-publish, payload-published-last" atomic pair-publication pattern for their own cached-binary installs, plus consistent HTTPS-only URL validation and tar/zip-slip extraction defenses.
- The graph-visualization web UI (`graph-ui/`) had a **"kill arbitrary process" capability removed** from its Control tab, and its Vite dev-server proxy gained strict browser-`Origin` allowlisting (403 on any foreign origin) — both security-hardening deletions/tightenings tied to the daemon now owning the UI.
- **No CHANGELOG.md, AGENTS.md, CLAUDE.md, or `.specs/` directory exists anywhere in this repository** — a materially different engineering-contract convention from massa-ai's own repo. The repo's actual "changelog" is its merge-commit/PR history plus `README.md`.
- **A minor repo-hygiene gap, self-reported by its own `.gitignore`**: the ignore file excludes `soak-results/`/`soak-results-query-leak/` with the comment "never committed," but the actual soak-test output directories created and committed during this range are named `soak-mac*`/`soak30-*`/`soak-ql-mac*` — none of which match the ignored patterns — so ~15 log/CSV/JSONL artifact directories are currently checked into the repo root at HEAD, contradicting the stated intent.

## Architecture / capability changes

### The Session Coordination Daemon (PR #1139, the range's foundational change)

Prior to this range, each CBM (codebase-memory-mcp) session — MCP server, CLI call, hook invocation — appears to have run fully independently. PR #1139 introduces `src/daemon/` (13 new `.c`/`.h` modules) plus supporting foundation primitives, restructuring the whole product around one shared, mandatory, per-OS-account background daemon. This is described at the product level in `README.md`'s new "Session Coordination Daemon" section (`README.md:18-38` in the diff) and `docs/CONFIGURATION.md`, and at the code level across the following layered modules (read in full at HEAD as `.h` files; `.c` implementations, up to 6,114 lines for `ipc.c` alone, were read only for signatures/doc-comments given their size):

| Layer | File(s) | Responsibility |
|---|---|---|
| `foundation/private_file_lock.{c,h}` | New | Nonblocking SH/EX advisory locks inside a prevalidated private directory; tri-state return (`OK`/`BUSY`/`UNSAFE`/`IO`) throughout. |
| `foundation/lock_registry.{c,h}` | New | Generic writer-preference lock manager over named "resource keys," layered on `private_file_lock`; adds waiting-with-deadline and sticky cancellation tokens. |
| `foundation/macos_acl.{c,h}` | New | macOS extended-ACL clear/check for hardening private directories (deny-only-ACL predicate for ancestor directories). |
| `daemon/service.{c,h}` | New | The stable "rendezvous key" and `cbm_daemon_build_identity_t` (version, build fingerprint, cache fingerprint, protocol/store/feature ABI) plus `cbm_daemon_hello_compare()` → one of 7 conflict kinds or `COMPATIBLE`. |
| `daemon/daemon.{c,h}` | New | Process-local wire framing (12-byte `"CBMD"` frame header) and the `coordinator`: client-lease bookkeeping, job/watch subscription reference-counting ("first subscriber starts the physical resource, later ones join"), two-phase job cancellation. |
| `daemon/ipc.{c,h}` | New | The transport: owner-only Unix-domain sockets (POSIX) / generation-random current-user named pipes (Windows); "lifetime reservation" (is a listener running), "participant guard" (join a running daemon's group), "local transition" (one-shot CLI participant), and **crash recovery** — provably-safe stale-generation socket cleanup. |
| `daemon/version_cohort.{c,h}` | New | The "crash-safe exact-build admission" barrier atop ipc+service: `acquire` (join cohort, SH lock, fail BUSY under active maintenance), `reserve_exclusive` (EX for activation), `reserve_for_mutation` (full install/update/uninstall barrier: maintenance-intent EX → admission EX → lifetime EX, with a bounded quiesce callback). |
| `daemon/runtime.{c,h}` | New | Combines ipc+service+daemon into the wire protocol: `HELLO`, `HEARTBEAT`, `JOB_SUBSCRIBE/UNSUBSCRIBE`, `APPLICATION_REQUEST/CANCEL`, `ACTIVATION_SHUTDOWN`, `CLOSE_INTENT` (Windows named pipes have no client half-close), `STATUS`, `STOP` — all fixed-size wire structs with exact byte offsets frozen for compatibility (e.g. `CBM_DAEMON_RENDEZVOUS_REQUEST_SIZE 133`). |
| `daemon/host.{c,h}` | New | `cbm_daemon_host_run()` — the daemon process's actual main loop: first admitted frontend owns startup; final disconnect triggers ordered teardown (operations → watcher → UI → runtime); owns the UI's HTTP-thread reconciliation state machine. |
| `daemon/bootstrap.{c,h}` | New | Client-side: classifies the process role from argv (`STATELESS`/`DAEMON`/`WORKER`/`MCP_CLIENT`/`LOCAL_CLI`/`HOOK_CLIENT`/`DAEMON_CTL`) before any stateful init runs; the full probe→startup-lock→spawn-if-needed→connect state machine, with an **injectable `ops` struct** (`cbm_daemon_bootstrap_ops_t`) so this OS-boundary-heavy logic has a deterministic unit-test seam. |
| `daemon/application.{c,h}` | New | The RPC dispatch layer above authenticated transport: one MCP session per connection, workspace context, shared watcher subscriptions, daemon-owned index jobs, one update-check generation; injectable worker/update-check ops for testing. |
| `daemon/frontend.{c,h}` | New | The stdio bridge a thin MCP client process runs: relays stdin↔daemon↔stdout while a separate maintenance-monitor thread can request cooperative cancellation and `_Exit()` mid-request if activation demands it. |
| `daemon/project_lock.{c,h}` | New | Project-level SH/EX locking for graph mutations, with `"*"` as a global-wildcard EX lock blocking every named project. |
| `cli/activation_transaction.{c,h}` | New | The atomic binary-swap primitive (see Features below) — deliberately knows nothing about daemon coordination. |

**Design idioms used throughout** (worth noting for the Portable-ideas section): tri-state return codes (`OK`/`BUSY`/`UNSAFE`/`IO`) rather than boolean success/fail everywhere locks are involved; extensive `_for_test` seams compiled into production headers (not bolted on separately) so OS-boundary-heavy state machines (bootstrap, HTTP reconciliation, IPC startup races) get deterministic unit tests; explicit "fail closed" language throughout the doc comments for every ambiguous or unverifiable OS state.

### Cross-language mirroring in packaging wrappers

The Go (`pkg/go/cmd/codebase-memory-mcp/`), npm (`pkg/npm/install.js`), and PyPI (`pkg/pypi/src/codebase_memory_mcp/_cli.py`) thin wrappers each independently implement a smaller version of the same admission/pairing concept for their own package-manager-cached binary: a PID-liveness check for stale-lock reclamation (`pair_lock_windows.go` using `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`, conservatively treating access-denied as "still alive"; `pair_lock_other.go` for POSIX), HTTPS-only URL validation (parsed, not string-prefix-matched), tar-slip/zip-slip extraction-path defenses, and the same "authenticate the complete pair, then publish the payload last as the readiness signal" ordering discipline documented consistently across all three languages' comments.

### Graph UI / HTTP server

`src/ui/http_server.c`/`httpd.c` (both pre-existing, modified in #1139) are now daemon-owned rather than started per-session — "the UI is owned by the shared coordination daemon, so concurrent agent sessions do not start duplicate HTTP servers" (`README.md` diff). The Vite dev proxy (`graph-ui/vite.config.ts`) gained a hand-written origin-checking `bypass()` that 403s any request whose `Origin` header isn't in an explicit allowlist, matching a new backing test `tests/test_ui_dev_proxy_security.sh`. The Control tab's process-kill capability (`ProcessCard`'s `onKill`, `killProcess()`, and the `/api/process-kill` POST) was removed entirely (`graph-ui/src/components/ControlTab.tsx`).

## Features added

### 1. Session Coordination Daemon (see Architecture above)
- **Where:** `src/daemon/*`, `src/main.c`, `src/cli/bootstrap` wiring, `Makefile.cbm` (`DAEMON_SRCS`), `README.md`/`docs/CONFIGURATION.md`.
- **Depends on:** `foundation/private_file_lock.c`, `foundation/lock_registry.c`, `foundation/macos_acl.c`, mimalloc (vendored allocator), SQLite (vendored, patched — see below).
- **Gated:** not opt-in — "There is no opt-in setting for MCP servers or hook clients." Every daemon-backed session participates automatically.
- **Observability:** three owner-only NDJSON/structured logs under `${CBM_CACHE_DIR}/logs/`: `cbm-daemon.log` (lifecycle), `daemon-conflicts.ndjson` (admission conflicts), `activation-events.ndjson` (install/update/uninstall progress).

### 2. Atomic activation transactions (install/update/uninstall)
- **Where:** `src/cli/activation_transaction.{c,h}` (new, #1139); consumed by `cli.c`'s install/update/uninstall commands.
- **How:** stage a candidate beside the target (same filesystem, for atomic rename) → `commit()` (atomic publish, retains the old binary as backup, runs an optional post-commit validator that auto-rolls-back on failure) → `finalize()` (delete backup) or `rollback()`. Windows: if the retained backup can't be unlinked because its image is still mapped, `commit` safely registers it for delete-on-reboot and returns `DEFERRED` rather than failing.
- **Depends on:** `version_cohort`'s `reserve_for_mutation` barrier (ensures no other CBM process is active during the swap) and the runtime's `ACTIVATION_SHUTDOWN` wire op (asks the daemon and local CLI participants to drain first).
- **Gated:** always active for install/update/uninstall; not user-configurable.

### 3. Flag-based CLI (replaces raw inline-JSON tool invocation)
- **Where:** `src/cli/cli.c`, documented in `README.md` "CLI Mode" section.
- **How:** every MCP tool is now invocable as `cli <tool> --flag value` with flags auto-generated from the tool's JSON input schema; `cli <tool> --help` prints them. Adds `--progress` (force lifecycle/progress output to stderr when not an interactive TTY), `--json` (full MCP result envelope), and stdin-JSON input. Inline JSON positional args are kept for backward compatibility but documented as deprecated.
- **Gated:** always on; the old inline-JSON calling convention still works.

### 4. Memory-diagnostics framework (issue #581 fallout, PR #1252/`a3887001`)
- **Where:** `src/foundation/mem.{c,h}` (+602/+209 lines net), `src/foundation/mem_profile.c` (+325 new).
- **How (durable API, `mem.h:81-218`):**
  - **Three-way memory map** (`cbm_mem_map_collect`): `os_committed_bytes` (ground truth) vs. allocator-visible `live_bytes` (current-thread heap walk only) vs. an implicit `residual`. The design principle stated in the header comment is notable: *"an incomplete map announces itself instead of looking balanced"* — a blind spot shows up as a large residual, not as a falsely-reassuring zero.
  - `malloc_is_allocator_owned` is checked first: whether the configured allocator (mimalloc) is actually intercepting plain `malloc()` on this build — false here explains a zero `live_bytes` and is itself a named defect class ("a platform-parity defect in its own right (#581 on Windows)").
  - Size-class bucket histogram (8 buckets) localizes which allocation size is growing without per-callsite instrumentation.
  - **Allocator-ownership audit** (`cbm_mem_audit_ownership`) — probes ALL size classes, not just one, because an allocator override "can capture small allocations while large or huge ones go elsewhere... a leak at best and undefined behaviour at worst."
  - **Phase map** (`cbm_mem_phase_mark`/`_reset`/`_report_json`) attributes OS-committed-byte deltas between named marks to whichever phase is "open" — used when growth bypasses the allocator entirely (the actual Windows case), gated behind `CBM_MEM_PHASES=1` so the hot path pays one atomic load when off.
  - **Windows region census** (`cbm_mem_win_census`) — two independently cross-checking OS walks (`VirtualQuery` over the address space; `GetProcessHeaps`+`HeapWalk`) used to attribute a real measured "440 MB private vs. 34.7 MiB of arenas" gap to a specific memory pool rather than guessing between hypotheses ("guessing... costs a soak run per guess; asking the OS costs one pass"). Tracks base address + size of the largest private regions so growth can be matched to a specific allocation site by address stability. Gated behind `CBM_MEM_CENSUS=1` since `HeapWalk` locks every CRT heap.
- **Gated:** all census/phase features are off by default (env-var gated); the map/audit APIs are always-available diagnostics functions, not hot-path cost.

### 5. Local/remote CI-venue-parity unification
- **Where:** `scripts/package-release.sh` (new canonical archive/bundle step), `scripts/soak-legs.sh` (new canonical soak entry, replacing an inline `soak.yml`), `scripts/ci/{ensure-defender,preflight-docker,smoke-artifact,verify-shard-union,require-all-green,generate-sbom,new-protected-temp-root,clean-test-residue}.{sh,ps1,py}` (new canonical helpers), `tests/test_venue_parity_contract.sh` (new, 404 lines).
- **How:** the parity contract is a Python-driven whitelist walker that classifies every `run:` line in every CI workflow as provisioning / artifact-plumbing / canonical-call, and fails (naming file+line+remedy) for anything unclassifiable — run as "Step 0j" of `scripts/test.sh`, so local and CI test runs are provably calling the same entry points.
- **Gated:** always on, part of the default test gate.

### 6. VirusTotal release gate, its (reverted) tolerance mechanism, and the zero-tolerance tripwire
- **Where:** `scripts/ci/check-virustotal.sh`, `.github/workflows/release.yml`.
- PR #1340 added `TOLERANCE_ELIGIBLE` (prerelease-only) logic that could downgrade a BLOCKED verdict to TOLERATED only for single-engine, Microsoft, `!ml`-suffixed detections backed by real Windows-VM Defender-endpoint scan evidence (`scripts/ci/av-endpoint-verify.sh`, new, 153 lines) fetched and hash-matched via `gh release download`.
- PR #1341 reverted this completely one PR later. The gate is now unconditional: any detection, any engine, any artifact, any version blocks the release. A new `tests/test_vt_gate_zero_tolerance_contract.sh` includes an explicit **tripwire** — `grep -q "defender-endpoint-verification\|av-endpoint-verify"` over the gate script must find nothing — so reintroducing the reverted mechanism requires consciously deleting this test first.
- **Gated:** always on for release builds; not configurable.

### 7. Binary-composition security gate
- **Where:** `scripts/ci/check-binary-composition.sh` (new, 404 lines, introduced in #1344), wired into `scripts/package-release.sh` right after stripping.
- **How:** asserts the *absence* of malware-shaped capabilities in the release binary: no seam env-var strings beyond an explicit allowlist (so a *novel* `CBM_TEST_*` fails), no updater/release-download URLs, no SQLite load-extension symbols (with a positive control via `sqlite_compileoption_get` to prove the check itself works), and the ELF non-executable-stack property via `readelf`/`objdump`. A UI/HTTP-server-string check exists but is report-only (not yet enforced), pending a further `src/ui` refactor.
- **Gated:** always on for release packaging.

### 8. Nightly compiler-cache warming (`cache-warm.yml`)
- **Where:** `.github/workflows/cache-warm.yml` (new, 123 lines).
- **How:** a build-only (no tests), cron-scheduled (`17 2 * * *`) job across the full OS matrix (ubuntu x64/arm, macos-14, macos-15-intel, windows CLANG64 via MSYS2) that mirrors `scripts/test.sh`'s build phase exactly (for cache-key fidelity) using `ccache` with content-based staleness detection, solving the specific problem that GitHub Actions cache isolation lets a PR only restore caches written by its own ref or the base branch — and since the test workflow only runs on `pull_request`/`workflow_dispatch`, nothing had ever written a base-ref ("main-scoped") cache a fresh PR could fall back to.
- **Gated:** always on (scheduled + manual dispatch); not opt-in.

### 9. Prerelease release-channel correctness
- **Where:** `.github/workflows/release.yml` (PR #1303/`5250c249`).
- **How:** a version containing `-` (e.g. `v0.9.1-rc.1`) is marked `prerelease: true` on GitHub (never "Latest"), published to npm under the `next` dist-tag instead of `latest`, and MCP-Registry sync is skipped entirely for it (that registry has no channel concept). PyPI needed no code change (PEP 440 already treats `rc` as pre-release; `pip` only installs it with `--pre`).
- **Gated:** automatic based on version-string shape.

## Performance & efficiency changes

- **Launcher removal is a genuine latency/complexity win, not just a security fix**: per the #1316 commit body, "every daemon start, CLI call and hook fire loses a process spawn, a named pipe handshake and an stdio relay" that existed purely to route around the self-update constraint.
- **Release binaries are smaller**: stripping (PR #1328/#1332/#1338) removes the ~536 KB symbol table from every shipped binary.
- **CI cache-warming** (`cache-warm.yml`) removes cold-cache builds for the common case of a fresh PR branch, at the cost of one nightly scheduled build-only job per OS/arch combination.
- **Test sharding** (`shard_suites: true`, PR #1139) splits each C-suite leg across parallel shard jobs (ubuntu x3, windows x2), re-proving shard completeness every run via a dedicated job.
- **Attempted-but-reverted**: a per-connection thread pool (replacing "one thread per connection") was tried during the #581 investigation (`3cd1d338` "pool connection threads instead of one per connection") and explicitly reverted 1 day later (`7808eee5` "revert(daemon): drop the connection thread pool") — it did not survive into the shipped state, so it should **not** be counted as a delivered performance change.
- Memory-diagnostics instrumentation (mem-map, phase-marks, Windows census) is designed to cost nothing when off: env-var gated (`CBM_MEM_PHASES=1`, `CBM_MEM_CENSUS=1`), "off unless `CBM_MEM_PHASES=1`, so the hot path pays one atomic load."
- CI ccache adoption (content-verified compiler cache, `CCACHE_COMPILERCHECK=content`) extended across `pr.yml`'s Ubuntu/macOS/Windows legs, not just the new nightly warm job — real wall-clock CI savings, no number quantified in the diffs themselves.
- No numeric before/after latency or throughput benchmark was found for the daemon architecture itself (no `docs/BENCHMARK.md` change in range) — the closest quantified evidence is the memory-leak measurements above (1.1x vs. 53x growth) and the test-count/suite-count badges.

## Portable ideas

For each notable idea: **Portable** = broadly reusable in another memory/code-intelligence MCP project (including massa-ai) regardless of language/runtime. **Specific** = tied to this repo's C/native/Windows/AV internals and not directly transferable.

- **Portable — "announce blind spots as data, not silence."** The memory-diagnostics three-way map (OS ground truth / tool-visible / explicit residual) is a generic diagnostics-design principle: any monitoring tool that can only see part of a system should make the unseen part an explicit, growing number rather than let it default to "0 = fine."
- **Portable — count-bounded security allowlists.** `NETWORK:file:function:expected-count:justification` / `WRITE:file:expected-count:justification` — a gate that fails when the *actual* occurrence count of a dangerous primitive diverges from a declared count (not just "is it in the allowlist") catches new unreviewed occurrences automatically. Directly applicable to massa-ai's own use of `eval`-like dynamic execution, raw SQL string building, or subprocess spawning.
- **Portable — CI cache-warming for cache-isolated CI systems.** The specific lesson (a PR-triggered workflow that never runs on the base ref will never populate a base-ref cache a PR could fall back to; a scheduled build-only job fixes it) applies to any GitHub-Actions-based project with expensive builds, including massa-ai's own Turborepo/Bun CI.
- **Portable — venue-parity whitelist contract.** A script that walks every CI workflow's shell invocations and asserts they route through the same canonical entry points local developers use is a strong, generic anti-drift mechanism for any project running tests on multiple venues (local, multiple CI OSes).
- **Portable — "payload published last as the readiness signal."** The atomic multi-file publish ordering discipline (verify the whole candidate first, then publish the file that downstream code treats as "ready" last) recurs identically across this repo's C, Go, npm, and PyPI implementations — a solid general pattern for any atomic-install/update logic.
- **Portable — safe-destructive-path validation before `rm -rf`.** `scripts/path-safety.sh`'s `cbm_require_safe_build_dir`/`cbm_remove_build_dir` (reject anything but a single safe path component directly under `build/`, resolve symlinks, verify the physical path lands where expected) is directly reusable in any project's clean/build scripts, including massa-ai's own.
- **Portable — injectable-ops-struct test seams for OS-boundary-heavy state machines.** `daemon/bootstrap.h`'s `cbm_daemon_bootstrap_ops_t` (function-pointer struct for cohort-acquire/probe/startup-lock/spawn, swappable in tests) is a strong general pattern for deterministically testing code that otherwise depends on real OS process/lock semantics.
- **Portable — "a conjunction of two properties set in the same locked step is not independently observable."** The `#1309` test-design lesson (wait for the actual production invariant, not an artifact of test-observation timing) is a durable, language-independent concurrency-test principle.
- **Portable — governance-by-tripwire-test.** The VT zero-tolerance revert (`#1341`) enforces a policy decision not just by deleting code but by adding a test that greps the gate script's own text for the reverted mechanism's signature — making silent reintroduction require consciously deleting the guard first. Reusable for any "we decided never to do X again" policy.
- **Portable — never delete a file you can't prove you own.** Both the installer-script-left-beside-the-binary ("uninstall reports, never deletes it") and the general activation-transaction backup-retention design embody a conservative-uninstall principle worth adopting anywhere a tool manages files it didn't necessarily create.
- **Portable — "print the exact command instead of feigning self-update."** The core lesson behind the launcher removal and in-process-updater removal (an in-process updater is structurally a downloader — fetch, verify, extract, exec — and that shape alone will eventually get flagged by antivirus/heuristic scanners, or should be avoided even absent AV, on privacy/network-hygiene grounds) is directly relevant to any locally-installed agent tool that self-updates, including massa-ai's own installers.
- **Specific — the daemon's exact wire-protocol framing, byte offsets, and ABI version constants.** These are CBM-internal contract details, not reusable as-is, though the *pattern* (frozen stable "rendezvous" envelope decoupled from a separately-versioned "detailed operation ABI") is a portable protocol-versioning idea worth abstracting.
- **Specific — Windows named-pipe vs. Unix-domain-socket transport mechanics, `CLOSE_INTENT` frame for no-half-close platforms, ARM64 SQLite alignment, mimalloc TLS-callback mechanics under static MinGW, BSD-vs-GNU `mktemp` template quirks, MSYS2-specific CI plumbing.** These are real, well-documented platform gotchas but not portable beyond native/cross-platform C projects.
- **Specific — the exact AV/VirusTotal engine-name/verdict-suffix matching logic and Windows Defender endpoint-verification mechanics.** The *governance pattern* (above) is portable; the concrete implementation (matching `!ml` suffixes, Microsoft engine names, `MpCmdRun.exe` scans) is not.
- **Specific — the C preprocessor-based opt-in test-seam compilation (`#ifdef CBM_ENABLE_TEST_SEAMS`) and the seam-callsite-vs-stub distinction fixed in `#1346`.** The general idea (compile-time-gated test hooks; a static analyzer will eventually prove a "stubbed to true" condition is dead code) is language-agnostic, but the mechanism itself is C/preprocessor-idiomatic.
